# Подготовка документа к аудиту

## Что делает

1. **Карта блоков.** Документ разбирается на атомы: каждый абзац и каждая ячейка
   таблицы получают `block_id` и технический адрес (часть документа, индексы
   таблицы, строки, ячейки). Это то, что превращает «модель что-то нашла» в
   «страница 23, таблица 22, строка 31, ячейка 3».

2. **Карта страниц.** Внутри .docx нет номеров страниц — вёрстку решает Word при
   печати. Поэтому делается копия документа с невидимыми маркерами, Word
   экспортирует её в PDF, и маркеры ищутся постранично. Требуется Windows с
   установленным Word. Без него всё работает, но находки будут без номеров
   страниц.

3. **Нарезка на чанки.** Блоки собираются в части заданного размера. Граница
   всегда проходит между блоками — цитата никогда не разрывается пополам. В
   начало каждой части кладётся хвост предыдущей как контекст (он помечен и не
   проверяется).

## Запуск

```bash
"<skill>/scripts/run.cmd" prepare.py --source "D:\docs\Записка.docx" --preset standard
```

Рабочая папка по умолчанию — `<имя документа>__audit` рядом с исходником.

## Какой Python нужен

Системная установка **не требуется**. Достаточно встроенного (portable) Python —
именно так этот скилл и разрабатывался: все проверки на реальном документе
выполнялись runtime'ом программы Audion Docs AI, системного интерпретатора на
машине не было вовсе.

Нужны `python-docx` и `openpyxl`; для карты страниц ещё `PyMuPDF`, для PPTX —
`python-pptx`. В runtime Audion Docs AI всё это уже лежит.

### Два способа развернуть

**1. Портативная Audion Docs AI рядом — рекомендуется для организации.**
Скопируйте папку программы куда угодно: скилл сам найдёт её runtime со всеми
библиотеками. Ничего не устанавливается, права администратора и интернет не
нужны. Если папка лежит в нестандартном месте, укажите её один раз:

```bash
set AUDION_DOCS_AI_HOME=E:\TOOLS\Audion Docs AI
```

**2. Системный Python** с установленными библиотеками:

```bash
pip install python-docx openpyxl PyMuPDF python-pptx
```

### Как вызывать скрипты

На Windows команда `python` часто ведёт на заглушку Microsoft Store — она
существует, отвечает и ничего не запускает. Поэтому запускай скрипты обёрткой,
она сама подбирает рабочий интерпретатор:

```bash
"<skill>/scripts/run.cmd" prepare.py --source "D:\docs\Записка.docx"
```

На macOS и Linux — `run.sh` с теми же аргументами. Кандидаты проверяются не по
версии, а по импорту нужных библиотек, и берётся первый пригодный: `DOCS_AI_PYTHON`,
затем `AUDION_DOCS_AI_HOME`, затем runtime программы в обычных местах
(`?:\TOOLS\Audion Docs AI\runtime`, рядом со скиллом, в профиле пользователя),
и только потом `py` и PATH.

Проверить конкретный интерпретатор:

```bash
"<путь к python>" "<skill>/scripts/check_env.py"
```

Он покажет версию, наличие каждой библиотеки, доступность PowerShell для экспорта
через Word и подскажет команду установки недостающего.

## Платформы: где скилл работает

SKILL.md — открытый стандарт, поэтому эти скиллы загружаются не только в Claude
Code. Роли исполнителей описаны нейтрально (`reader` — быстрый чтец, `analyst` —
рассуждающий), а какая это модель, решает `--platform`:

| `--platform` | Агент | reader | analyst |
|---|---|---|---|
| `claude` | Claude Code | haiku | sonnet |
| `codex` | ChatGPT / Codex | gpt-5.6-terra | gpt-5.6-sol |
| `grok` | xAI Grok (SuperGrok) | grok-4.3 | grok-4.5 |
| `gemini` | Gemini / Antigravity | gemini-3.6-flash | gemini-3.1-pro-preview |
| `generic` | любой другой | самая быстрая | самая сильная |

Куда класть скиллы: Claude Code — `~/.claude/skills/`, Codex и Antigravity —
`~/.agents/skills/`, Grok читает и `~/.grok/skills/`, и каталоги `.claude`.
В чат-интерфейсах ChatGPT, Grok и Gemini скилл загружается файлом — собрать
архивы `.zip` и `.skill` можно так:

```bash
"<skill>/scripts/run.cmd" package_skills.py
```

**Важное ограничение.** Скиллу нужен локальный Python и — для карты страниц —
установленный Microsoft Word. Полный цикл поэтому работает там, где агент имеет
доступ к вашим файлам и оболочке: Claude Code, Codex CLI, Antigravity CLI, Grok
Build. В веб-чатах документ придётся загружать, Word недоступен — работайте с
`--no-pages` либо приложите готовый PDF маркированной копии через `--pdf`.

## Пресеты: сколько внимания стоит документ

Главный параметр — `--preset`. Он задаёт и нарезку, и то, какая модель будет
читать каждый чанк. Проза режется мельче, таблицы крупнее: прозу читают строка
за строкой, таблицы — сравнивая строки между собой, и для этого нужен широкий
обзор.

| Пресет | Когда | Проза | Таблицы | Модель |
|---|---|---|---|---|
| `scan` | 1000+ страниц, черновик, «что там вообще» | 12k | 16k | Haiku, low |
| `standard` | обычная записка, том, ПКР — основной режим | 16k | 48k | Sonnet, low / medium |
| `deep` | небольшой, но ответственный документ, расчёты, спорные разделы | 12k | 32k | Sonnet, medium / high |

На проектной записке в 200 страниц это даёт: `scan` — 49 чанков целиком на Haiku,
`standard` — 20 чанков (5 прозы на low, 15 таблиц на medium), `deep` — 28 чанков
(23 таблицы на high).

Размеры подобраны по замерам: Haiku на 48-тысячном чанке отмечает 12 блоков из
541 и к концу текста явно устаёт, а на 12–16 тысячах держит внимание. Sonnet на
крупном табличном чанке, наоборот, пересчитывает проценты прироста и находит то,
что пропустили платные API-прогоны — ему широкий обзор нужен.

Параметры:

- `--preset` — `scan` / `standard` (по умолчанию) / `deep`.
- `--text-chunk-tokens`, `--table-chunk-tokens` — переопределить размеры вручную,
  если пресет не подходит.
- `--overlap-tokens` — контекст из предыдущей части, по умолчанию 2000.
- `--min-chunks` — заставить нарезать минимум на N частей (для коротких документов).
- `--no-pages` — пропустить экспорт в PDF. Быстрее, но находки останутся без
  номеров страниц.
- `--pdf` — использовать готовый PDF вместо экспорта. **Важно:** это должен быть
  PDF маркированной копии из рабочей папки (`*__marked.docx`), а не исходного
  документа — иначе маркеры не найдутся. Если Word недоступен, откройте
  маркированную копию и сохраните её в PDF вручную.

## Что получается

```
<work_dir>/
  manifest.json      список чанков, размеры, статусы
  block_map.json     все блоки документа с адресами
  render_map.json    блок → страница
  chunks/            chunk_001.md … готовые к чтению части
  findings/          пусто, сюда пишет docs-ai-audit
  *__marked.docx     копия с маркерами (служебная)
  *__marked.pdf      экспорт для карты страниц (служебный)
```

## Глубина проверки

Каждому чанку в манифесте проставляется `profile`:

- **`light`** — сплошной текст, ошибки в нём формальные (опечатки, пунктуация,
  типографика). Достаточно быстрой модели без размышления.
- **`deep`** — таблицы, плотные числа, нумерованные ряды. Здесь живут ошибки,
  которые видно только сопоставлением: несходящиеся суммы, невозможные величины,
  пропуск в последовательности. Такому чанку нужна модель с рассуждением.

Решение принимается по трём измеримым признакам: доля табличных блоков, плотность
цифр в тексте и длина непрерывного числового ряда. Причина записывается в
`reasons`. Пороги — в `scripts/docs_ai_core/profiling.py`.

Для проектных записок с таблицами это обычно даёт почти сплошной `deep` — и это
правда о документе, а не дефект разметки.

## Оценка токенов

Считается по составу текста: латиница ≈ 4 символа на токен, остальные письменности
(кириллица, греческий, CJK) ≈ 1,8. Поэтому заказанные 48 000 — это действительно
около 48 000, а не вдвое больше.
